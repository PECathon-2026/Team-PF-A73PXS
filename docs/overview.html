PrivacyLens

A browser agent that lets an AI do a task for you, such as paying for a cart or logging in, without the AI ever seeing your private details. Built for PECATHON'26, problem statement PS-004.

Compute what is sensitive locally. Reason globally only on sanitized data.

Is it ready?

The main app is built and working. It runs on your computer, opens in a browser, and completes all six test tasks offline with the built-in Mock planner. It also works with Google's Gemini as the AI.

What was built

1. Finds private data

Cards (Luhn checksum), Aadhaar (Verhoeff checksum), PAN, email, phone, OTP, passwords, API keys, IP addresses, UPI, IFSC, CVV, plus names, addresses, birth dates and health details from context. It also reads the page structure (password fields, card fields, call tiles) and detects faces.

2. Hides it

Each value becomes a labelled placeholder and the screenshot is blacked out with solid boxes. The real values stay in memory on your computer only. The AI still sees enough structure to do the task.

3. Checks everything before it leaves

An outbound guard scans every message for real values and canary secrets. If anything is wrong, or the check itself fails, nothing is sent.

4. Lets the AI act safely

The AI proposes one action at a time. A validator rejects invalid targets, guessed secrets and off-site links. Payments and other irreversible steps ask you first.

5. Types your secrets locally

The AI only says "put the card number here". Your computer types the real value at the last moment. The AI never sees it.

6. Proves it with tests

100% task success, 100% recall, 0 leaks in the measured runs, and 20 of 20 adversarial cases pass. All numbers come from one evaluation file.

How it works

Each step of a task goes through the same pipeline. Green boxes stay on your computer. The blue box is the only part that talks to the AI.

on your computer1. Look at the pageText, form fields, accessibility tree, screenshot
on your computer2. DetectPatterns with checksums, page structure, context rules, faces
on your computer3. HidePlaceholders and black boxes; real values go to the vault
on your computer4. GuardBlock anything unhidden. Fails closed
the AI5. DecideGemini or Mock reads the hidden view and proposes one action
on your computer6. ValidateReject bad targets, guessed secrets, off-site links
on your computer7. Ask youFor payments and other irreversible steps
on your computer8. ActTypes real values locally. The browser can only reach this computer

What you see

The main screen

One task box, one button, one chip per task, the live page, one switch, one status line and one sentence about what it is doing. No technical words.

What you see while it works

Private items on the page are covered by a soft frosted overlay with a small "Hidden" tag. This overlay is drawn on your computer only.

"See what the AI sees"

Flip the switch and the view crossfades to exactly what the AI receives: private areas are solid black.

The approval sheet

Like Apple Pay: one plain sentence, a big Approve button, a quiet Cancel, and a "Why am I asked?" link. Routine steps never interrupt. It is a bottom sheet on phones.

Why was each thing hidden?

Tap the status line ("9 things hidden · nothing private shared") for a plain-language reason for every hidden item.

For the judges: "How it works" and the leak test

A small link at the bottom opens the technical view: the pipeline for the current run, the raw page text next to the exact text the AI received, validation and approval decisions, evaluation results, privacy settings (switch types off, add your own "Always hide..." rule), the AI choice, and the Run leak test button. That button sends a planted fake secret past the sanitizer on purpose. The guard must stop it, and the main status line then reads "Stopped 1 unsafe message".

On a phone

Open the same address on a phone on the same Wi-Fi. It joins the current run, shows the AI view, and can approve steps. The first answer from either device wins.

Set it up

Windows

  1. Install Python 3.11 or newer.
  2. Open the project folder and double-click run.bat. It creates a private environment, installs the packages, downloads the Chromium browser used by the agent, copies .env.example to .env and starts the server.
  3. Open http://localhost:8000 on the same computer.
  4. If Windows shows a firewall prompt, allow it on Private networks so a phone can connect.

macOS and Linux

./run.sh

Written the same way but not run on macOS or Linux yet. On Linux, Playwright may also need playwright install-deps.

Use it

  1. Pick a chip, such as "Pay for my cart", and press Go.
  2. Watch the narration line. Approve when the sheet asks.
  3. Flip See what the AI sees to compare the real page and the AI's view.
  4. Open How it works and press Run leak test.
  5. To watch an attack get stopped, choose the AI "Offline test AI that obeys the page" in How it works, then run "Leave feedback".

Phone as an approval remote

  1. On the PC, run ipconfig and note the IPv4 address.
  2. On a phone on the same Wi-Fi, open http://<that address>:8000.
  3. Start a task on the laptop using localhost. The phone shows the same run and can approve.

Use Gemini (optional)

  1. Create a key at aistudio.google.com/apikey.
  2. In .env, set GEMINI_API_KEY= to the key and GEMINI_MODEL=gemini-3.5-flash-lite. Never share the key or commit .env.
  3. Run python scripts/check_gemini.py to see which models answer.
  4. Choose Gemini under How it works. If a model is busy, the app tries the models in GEMINI_FALLBACK_MODELS.

The free tier has a daily limit. For a demo, use Mock.

Honest limits

  • The demo server has no password and listens on the whole network so a phone can join. Use it only on a network you trust.
  • Gemini receives text only. The blacked-out screenshot is shown to you but is not sent to the AI.
  • Detection is rule-based plus a Haar face detector. There is no learned named-entity model, so unusual names in free text can be missed.
  • Some normal text can be hidden by mistake, for example a version like 1.2.3.4 looks like an IP address.
  • Leak claims cover the six test pages and two paths (the AI message and the browser network), not the whole web.
  • Not built: a local AI through Ollama (the offline mode uses the scripted Mock planner). Firefox could not be tested on the development machine.
